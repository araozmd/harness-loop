## Context

Two docs, one slice, because they are cited together: `docs/UMBRELLA.md` (485 lines, 19
headings, no diagram) is the doc a human opens to learn how one feature runs across several
repositories, and `docs/CONFIG-LAYERING.md` (117 lines, 5 headings, no diagram) is the doc
they open when a teammate asks "do we share one `CLAUDE.md`?". Both are also contracts.

**UMBRELLA** is read by **six suites** by heading slice or by phrase (`tests/test_install.sh`
on the **installed** copy — the `The thin child` section's Prose-tier row and the glossary D1
sentence; `tests/test_planner_topology.sh` — the `Manifest reference` section;
`tests/test_promote.sh` — the `Promoting a single install to a coordinator` section, nine
sentence pairs; `tests/test_umbrella_01_coordinator.sh` — `contract artifact`, `exactly one`,
`Every emitted slice`; `tests/test_umbrella_13_standalone.sh` — the `Migrating an existing
child` and `the way back` sections; and our own `tests/test_docs_for_humans.sh`, whose slice-3
row `F03_R8_sibling_citations` reads the landing-record pointer **inside UMBRELLA**). Outside
`tests/`, `docs/UMBRELLA.md` is cited on **60 lines**: 46 carry the token `docs/UMBRELLA.md`
and 14 the bare `UMBRELLA.md` (link text, a relative link target, or a suite label). They are:
two role prompts (`agents/architect.md` ×1, `agents/orchestrator.md` ×1), `store/local.md` ×1,
`harness-install.sh` ×10 (eight comments or printed usage text, one printed operator hint, one
comment that says UMBRELLA is unrelated), `harness.config.yaml` ×4 (comments in the shipped
seed), `umbrella.manifest.example.yaml` ×2 (comments), `docs/RATIONALE.md` ×1 (the D11 ledger
row), the human docs `docs/INSTALL.md` ×2 and `docs/README.md` ×1, `docs/CONFIG-LAYERING.md`
×2 (a doc this slice moves), `docs/agents/INSTALL.md` ×4 (three heading-anchored, one plain),
`docs/agents/README.md` ×2 (one plain pointer, one layout listing), and the 20 suite lines of
the six suites above. **No generated glue** (`.claude/`, `.agents/`, `.opencode/`, `.codex/`,
`.pi/`) and no `AGENTS.md` row cites either doc, so `sh harness-install.sh --self` has nothing
to regenerate here and is run only to prove it (R9).

**CONFIG-LAYERING** is read by **two suites** (`tests/test_install.sh` — 13 installed-copy
phrase pins across two blocks, the installed `The three layers` pointer-stub sentence, and
one installed-file existence check; `tests/test_feedback_config.sh` — the `## The three

`docs/CONFIG-LAYERING.md` and 24 the bare `CONFIG-LAYERING.md` (link text, link targets, a

`docs/INSTALL.md` ×1, `docs/README.md` ×1, `docs/UMBRELLA.md` ×1 (a doc this slice moves),
`docs/agents/INSTALL.md` ×1 (plain), `docs/agents/README.md` ×2 (one plain pointer, one layout
listing), and the 44 suite lines (`test_install.sh` ×39, `test_feedback_config.sh` ×5). The
`docs/INSTALL.md` further-reading line names both docs and is counted once in each inventory.
The frozen baseline fixture `tests/fixtures/frontend-v0.78.1/` (22 lines, UMBRELLA only), the
board, the changelog, `progress/` and earlier specs are history and are not citations.

Measured on this branch at its merge base with `origin/main` (`1fe1bf29`, the E39-F03 tip,
VERSION `0.112.0`; `origin/main` is `9188a93d`, the E39-F03 merge, same VERSION):
`tools/docs-move-check.sh origin/main` → `0 vanished tokens, 0 dropped lines, 0 moved lines,

`sh tests/test_docs_for_humans.sh` → all rows pass (the anchor lint is armed; every

`HARNESS_BODY_PROSE` lists `docs`, so all four files ship to every install; the installed-copy
suites keep reading an installed copy, at the new path.

The human reader needs five things from UMBRELLA: what an umbrella is and when it is engaged,
how to stand one up (the cascade, the landing audit, the layout of coordinator and children),
what a thin child is and how to convert or detach one, what `--shared-repo` buys, and how a
cross-repo feature runs (slices, the merge order, the integration gate, when it is `done`). They
need three things from CONFIG-LAYERING: which files are project, personal and user-global, what
the installer ignores for them, and how personal prompt files relate to the committed ones.
Everything else — the exit-code table, the pristine-only refusal text, the two path bases, the
six-step coordinator loop, the promotion refusals, the manifest keys, the fix-worktree allowlist,
the feedback non-inheritance rule — is exact contract that agents and suites rely on and moves
**verbatim** to the machine layer.

**Why CONFIG-LAYERING is split in full, not kept as the human doc.** The lighter treatment the
slice plan allowed — keep the 117-line doc as the human doc, add a diagram, register it — was
considered and rejected on three facts: (1) the text carries two feature ids (`E30-F01`,
`E32-F01`), so a registered copy reds slice 1's archaeology lint until edited, and an edit to a
sentence 13 installed-copy pins read is exactly the in-place rewording C2/C3 forbid; (2) its
sentences are pinned by two suites and one role-independent installer comment, i.e. they are
contract, and the epic's success criterion is that contract text lives under `docs/agents/`;
(3) one shape for every pair keeps the suite rows the same helpers (D6). What stays light is the
human doc: budget **100** lines, one diagram, eight pinned sentences.

The slice-1 review rejected a plain-language absolute that was false; the slice-2 review found
a spec check command that could not run and plan text that differed from the shipped wording;
the slice-3 review found a diagram node that claimed a check the preflight does not make and a
sentence that listed a tool's inputs incompletely. This slice therefore pins every human
sentence (R5, R7) with each exception stated, lists **all** members wherever a sentence
enumerates (the prose tier's four paths, the program tier's three paths plus the example files,
the four allowlisted personal files), names the over-claims a rewrite of these docs tends to
produce (an umbrella that is "a monorepo", an audit that "commits for you", a loop that "merges
for you", a `--thin` that "converts every child", a `done` that arrives "as soon as" slices are
done, a `.gitignore` that "ignores the whole" `.claude/`, personal files that "override the
project"), pastes the exact text the Builder ships, and uses only check commands that run on
this branch as written.

`specs/architecture.md` is absent in this repository; the ADR set under `specs/adr/` is present
(ADR-0001 … ADR-0011), so the `## Architecture alignment` section below cites it (graceful
degradation per `agents/architect.md`). Stage is `production` (`specs/product.md`).

## Business rules

**Decisions.**

- **D1 — Both documents move whole; both human docs are new text.** `docs/agents/UMBRELLA.md`
  is the 0.112 `docs/UMBRELLA.md` **entire** — H1, all 19 `#`/`##`/`###` headings in base
  order, every fenced block — and `docs/agents/CONFIG-LAYERING.md` is the 0.112

  exactly two kinds of difference: an announcement blockquote inserted after the H1; and
  relative link targets retargeted so they resolve from `docs/agents/` (C2). A keep-or-move
  triage was rejected for the slice-2/slice-3 reason: six suites slice UMBRELLA by heading and
  assume adjacency, two slice CONFIG-LAYERING the same way, so moving everything keeps every
  re-point a pure path substitution (C3). Both human docs are written fresh under their own
  headings and share **no** heading slug with their counterpart, so two files never carry the
  same anchor.
