# Docs for humans, slice 4: UMBRELLA + CONFIG-LAYERING split — Test Contract

> The traceability matrix: every R-id in the `.spec.md` maps to a concrete, executable test,
> and every row names the mutant that kills it. The Reviewer fails the feature if any R-id
> lacks a passing test, or if a named mutant survives that is not a listed known limit.
>
> **Suite.** The slice-1 suite `tests/test_docs_for_humans.sh` (DH) gains the rows below under a
> `# ---- E39-F04` comment; new row functions are named `F04_R<n>_<slug>` (the `R<n>` is this
> spec's R-id); the dispatch-completeness sweep already matches them. The house helpers are
> reused, never duplicated: `slice`, `unfenced`, `folded`, `mermaid_blocks`, `has_heading`,
> `nlines`, `link_targets`, `broken_links`, `anchor_problems`, `mirror`, `registry_each`,
> `index_rows`, `section_diagram`, `shape_problems`, `diagram_problems`; the only helper this
> slice generalises is the changelog check (`changelog_problem`). Rows that mutate a doc copy it
> under `$T` first and never touch `$ROOT`; the suite never reads `VERSION` as a literal and never
> git-diffs a DO-NOT-TOUCH file against `main`. Exit codes are asserted as `rc -eq N`. Installer
> behaviour (R11 shipping) lives in `tests/test_install.sh`; the move proof (R1's
> `docs-move-check.sh` clause) and the path-only diff (R8) are Reviewer behavioural checks because
> a permanent suite must not diff against `main`.
>
> **Mutants.** Each row names the smallest edit that must turn it RED. The Reviewer's mutation
> campaign applies each one in isolation on a copy (`cp` / `mv …mutbak` discipline from
> `agents/reviewer.md`), confirms the mutation applied (`grep` the planted text first), and
> restores between mutations. A path written `<agents>/…` below is a link target relative to
> `docs/agents/`, not a repository path.

## Behavioral / end-to-end checks

- **Render.** Open the branch on GitHub (or a Mermaid-capable preview): all three diagrams
  render; the layout shows the coordinator `.harness/`, the manifest and two children with
  `umbrella.root` dotted edges; the loop shows the single `done` edge leaving the integration
  node and the `failed` stop; the layers diagram shows the three layers and the dotted
  "additive only" edge back to the project layer.
- **Five-minute read.** Read `docs/UMBRELLA.md`, then `docs/CONFIG-LAYERING.md`, top to bottom.
  Over five minutes for the pair, or any paragraph that needs a second read, is a rejection with
  the paragraph named. Then, for every absolute in either doc (`never`, `always`, `nothing`,
  `every`, `all`, `only`), open the owning counterpart section from the plan's *Accuracy tables*
  and confirm the sentence; a sentence the contract does not support is a rejection even if the
  regex pin passes. For U5 and L6, count the enumerated members against the owning table (4 + 3
  paths and "the example files"; 4 allowlisted files).
- **Move proof.** `sh tools/docs-move-check.sh "$BASE"`: exit 0, `0 vanished tokens, 2 dropped
  lines, <M> moved lines, 3 human docs examined`; the two `DROPPED-LINE` lines are exactly
  `docs/RATIONALE.md:116` and `:118`. Then, in bash, `diff <(git show "$BASE":docs/UMBRELLA.md)
  docs/agents/UMBRELLA.md` (blockquote + five lines) and the same for CONFIG-LAYERING
  (blockquote + four lines).
- **Path-only diff.** The R8 `git diff -U0 … | uniq -u` command: exactly two survivors, the
  old and the new `for _f in` line of `test_docs_for_humans_installed_contract`.
- **Citations.** `python3 tools/doc-cite-check.py` at the repo root: exit 0. Then, in a scratch
  mirror, revert the installer's usage line to `docs/UMBRELLA.md` and rerun with `--root` on that
  file: exit 1 naming `harness-install.sh`.
- **Install.** `sh harness-install.sh --agents=all <tmp-target>`: all four docs present under
  `<tmp-target>/.harness/docs/` and identical to source; the installed `harness.config.yaml`
  comments cite `docs/agents/UMBRELLA.md`; `sh harness-install.sh --self` leaves `git status`
  clean.
- **Sibling docs and code.** `git diff --numstat "$BASE" -- agents/architect.md agents/orchestrator.md
  docs/RATIONALE.md docs/agents/INSTALL.md docs/agents/README.md harness-install.sh
  harness.config.yaml store/local.md umbrella.manifest.example.yaml` prints, in git's path order,
  added/deleted `1 1`, `1 1`, `2 2`, `3 3`, `2 0`, `9 9`, `4 4`, `1 1`, `2 2`, and every changed
  line differs only in a path token or is one of the two inserted index rows.
- **Mutation campaign.** Apply each row's mutant in isolation; every one reds its row; restore.
