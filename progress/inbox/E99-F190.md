# Fix — the Reviewer's "self-improving" clause must not invite edits to installer-owned files (GitHub #349)

## Problem / who
Reviewers in installed projects. GitHub #349 (harness-feedback, v0.111.0) reports this. In an
installed target, a Reviewer followed `agents/reviewer.md` "Self-improving the harness" ("you may
update the harness itself: tighten `AGENTS.md`, an agent prompt, or a template") and appended a
step to `.harness/agents/builder.md`. The next `init.sh` failed its drift guard (`init.sh:149`),
because `tools/harness-owned-paths.sh` classifies `agents/`, `docs/`, `tools/` and the templates
as installer-owned, and the session gate went red. Committing the edit does not help either:
the next upgrade overwrites it. This is still true on main (v0.115.3, `agents/reviewer.md:428-431`).
`docs/agents/HARNESS.md:43` and `docs/CONCEPTS.md:24` repeat the claim without the condition.

## Intended fix
- `agents/reviewer.md` "Self-improving the harness": make the clause depend on the layout.
  - **In the harness's own source repository** (no `.harness/` directory at the repository
    root), the Reviewer may still tighten `AGENTS.md`, an agent prompt or a template.
  - **In an installed project** (`.harness/` exists), those files are installer-owned: the
    drift guard in `init.sh` fails on any edit, and the next upgrade overwrites it. There the
    Reviewer records the lesson in the harness-root-relative `progress/lessons.md`, which is
    project-owned, and, when the gap fits one of the four triggers, appends an upstream report
    under **Reporting harness defects**. It never edits `.harness/agents/`, `.harness/docs/`,
    `.harness/tools/`, the templates or the generated glue.
- `docs/agents/HARNESS.md:43` and `docs/CONCEPTS.md:24`: qualify the claim the same way. Keep
  the CONCEPTS C6 pin phrase "may change the harness so a failure cannot recur" true.
- Tests (new suite `tests/test_reviewer_self_improve.sh`):
  - pin the installed-target rule (no edit to installer-owned paths; lessons ledger; upstream
    report);
  - ban the old unconditional sentence;
  - give each pin a mutant.
- VERSION PATCH bump plus a CHANGELOG entry. The PR body says "Fixes #349".

## How to verify
- `bash tests/test_reviewer_self_improve.sh` and `bash tests/test_docs_for_humans.sh` pass.
- `./init.sh` passes, `doc-cite-check` reports 0 findings and `docs-move-check origin/main`
  exits 0.
