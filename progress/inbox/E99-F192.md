# Fix — test-drift-check cannot waive a test whose name contains a spaced em dash (GitHub #353)

## Problem / who
Builders and Reviewers that waive path-only test drift. GitHub #353 (harness-feedback, filed at
v0.105.1) reports this, and it is still true on main (v0.115.5). The waiver grammar is
`waive-test-drift: <exact test name> — <reason>`. The parser in `tools/test-drift-check.sh`
(around lines 108-125) splits at the FIRST spaced em dash. A test whose attributed name itself
contains " — " (for example a describe title such as `A R8 — the download entries`) therefore
gets a truncated name that never matches. The tool reported "7 findings, 0 waived" with
exact-name waivers in place.

## Intended fix
- Match a waiver against the finding names instead of guessing where the name ends. A waiver
  line waives a finding when the line's text after `waive-test-drift:` starts with that
  finding's exact name followed by a spaced em dash and a non-empty reason. When several names
  qualify, take the longest. Lines that match no finding keep today's malformed or unused
  diagnostics.
- If the tool's structure makes the above awkward, an acceptable alternative is to split at the
  LAST spaced em dash, provided reasons with an em dash are still handled. Pick the option that
  is unambiguous, and document the rule in the tool's header and in its contract text, wherever
  the waiver grammar is described (`grep -rn "waive-test-drift" agents docs`).
- Tests (in the existing test-drift suite):
  - a name containing " — " is waived by its exact-name waiver;
  - a reason containing " — " still parses;
  - a near-miss name (a prefix of the real one) does not waive;
  - each case is RED before the fix.
- VERSION PATCH bump plus a CHANGELOG entry. The PR body says "Fixes #353".

## How to verify
- The test-drift suite and `tests/test_docs_for_humans.sh` pass if docs change. `./init.sh`
  passes, `doc-cite-check` reports 0 findings and `docs-move-check origin/main` exits 0.
