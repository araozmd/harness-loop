# Fix — PR-loop robustness: no-CI repos, transient gh failures, Codex "Unknown error", missing needs-human label (GitHub #355, #356, #357)

## Problem / who
Operators running `/sdd-pr-loop` in installed projects. Three harness-feedback reports (v0.115.1)
describe three bugs, all still present on main (v0.115.5):
1. **#355:** `ci_required_gate`, in the `/sdd-pr-loop` command emitted by `harness-install.sh`,
   treats a PR with no checks at all (no CI workflow, no branch protection) as "required CI
   unreadable" and hands it to needs-human on every run. The PR can never merge through the
   loop. Expected behaviour: no required checks on an unprotected base means the CI gate passes.
   Distinguish "no checks configured" from "could not read".
2. **#356:** `tools/wait-for-codex.sh` replaces a failed issue-comment or reaction fetch with an
   empty list (for example `|| echo '[]' > reactions.json`, around lines 630-650). A transient
   `gh` API failure then looks like "no Codex activity" and yields a false exit 5 ("Codex App
   most likely not installed"). Also, a Codex reply on the PR that says "Unknown error" (instead
   of a review) is not detected, and the watcher polls to the ceiling (exit 2).
   Expected behaviour:
   - a failed fetch is "unknown". It must never count as evidence of absence, so it must not
     drive the first-response exit 5;
   - a Codex error reply is reported as its own distinct outcome or diagnostic.
3. **#357:** every `gh pr edit … --add-label needs-human >/dev/null 2>&1 || true` in the
   `/sdd-pr-loop` command and the tools discards errors. When the label does not exist in the
   repository, the hand-off fails silently: no label and no signal. Expected behaviour:
   - create the label if it is missing (`gh label create needs-human … || true`), then apply it;
   - if applying still fails, print a visible warning naming the PR, so the hand-off is never
     silent.

## Intended fix
- Fix the three issues above in `tools/wait-for-codex.sh`, `tools/pr-gate.sh` (if it applies
  labels) and the `/sdd-pr-loop` emitter in `harness-install.sh`.
- Regenerate the glue with `sh harness-install.sh --self`; never hand-edit `.claude/`,
  `.opencode/` or `.agents/`.
- Keep every existing exit-code contract. Document any new exit code or outcome in the command
  text and in `docs/agents/WORKFLOW.md` where the codes are tabled, with exact wording and no
  over-claims.
- Tests, extending the existing pr-loop and wait-for-codex suites, each RED before the fix:
  - a no-checks PR passes the CI gate;
  - an unreadable CI result still fails closed;
  - a failing comments or reactions fetch does not produce exit 5;
  - a Codex "Unknown error" reply is surfaced, not left to time out;
  - a missing label is created, or the failure warns visibly.
- VERSION PATCH bump plus a CHANGELOG entry. The PR body says "Fixes #355, fixes #356,
  fixes #357".

## How to verify
- The pr-loop, wait-for-codex and pr-gate suites pass, and so do the docs suites if docs change.
  `./init.sh` passes. A second `--self` leaves the tree clean. `doc-cite-check` reports 0
  findings and `docs-move-check origin/main` exits 0.
