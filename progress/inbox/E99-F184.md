# Fix — readiness-check: a `delete` verb, and the contract says what the tool really checks

## Problem / who
Spec authors (the Architect) and the Reviewer, who reject on a readiness-check exit 1.
1. `tools/readiness-check.py` has no verb for a file the feature removes. A plan that names a
   file to delete in `## Files to change` (or a task or test that mentions it) passes at
   spec-ready, then fails with `unresolved-path` once the Builder deletes the file. That makes
   the Reviewer's check 9 reject. E39-F05 hit this with `docs/BASELINE-0.78.1.md` and had to
   rewrite the refs with a `<docs>/` placeholder prefix. Every future feature that deletes a
   file hits the same rejection.
2. `docs/agents/SPEC-FORMAT.md:227` and `agents/architect.md:220` say a `path:name` symbol is
   checked "anywhere". But `check_row` in `tools/readiness-check.py` returns before any symbol
   check on a files row whose verb is `add`, and skips everything on `create`. So the contract
   claims more than the tool checks.

## Intended fix
- Add `delete` (consider aliases `remove`/`move`, but keep it minimal and documented) as a plan
  `## Files to change` verb. A first-cell path in a `delete` row resolves whether or not the file
  exists (before and after the Builder deletes it), the way `create` declares a path.
  References to that path in tasks and tests resolve through the declaration too. Symbols in a
  `delete` row are not checked.
- Update the grammar in `docs/agents/SPEC-FORMAT.md` (*Implementation readiness*) and the
  `agents/architect.md` readiness paragraph. Document the `delete` verb, and make the `path:name`
  wording true: checked in tasks/tests units and in files rows that neither create nor add.
  Update the human `docs/SPEC-FORMAT.md` readiness bullet only if it becomes untrue. Its current
  text says "unless the files row creates or adds", so mention delete there too if that
  sentence would now be wrong.
- Regenerate glue with `sh harness-install.sh --self` if any emitted text changes. Never
  hand-edit `.claude/`.
- Tests in `tests/test_readiness_check.sh`:
  - a deleted path in a `delete` row resolves both before and after the file is removed;
  - a task that names it resolves;
  - the same path without the declaration is still `unresolved-path`;
  - each pin fails without the fix.
- VERSION PATCH bump + CHANGELOG entry (🐛).

## How to verify
- `bash tests/test_readiness_check.sh` green, plus the suites that pin the contract text
  (`tests/test_docs_for_humans.sh`, `tests/test_spec_format*` if present). `./init.sh` ok.
- `python3 tools/doc-cite-check.py` 0 findings; `sh tools/docs-move-check.sh origin/main`
  exit 0. Any contract edit is an intended change, not a move.
