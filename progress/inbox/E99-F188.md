# Fix — state the readiness-check `.harness/<file>` limit; make the update-check timing bounds sleep-tolerant

## Problem / who
1. `tools/readiness-check.py` never flags a typo in a file directly under `.harness/`, such as
   `.harness/typo.py`. Making `.harness/` a known root for such paths was measured across every
   spec in this repo, and it adds 29 false `unresolved-path` findings. Those are correct
   references to files that exist only in an installed target: `.harness/.harness-version`,
   `.harness/jira.pat`, `.harness/workers.json`, install stamps. The tool cannot tell those from
   a typo, so the behaviour is right and stays. But neither the contract nor the module
   docstring names this case.
2. `tests/test_update_check.sh` R3 C8 and C8c bound the gate's wall-clock time (about 4 s). A
   machine that sleeps mid-run fails them: one full-suite run measured 903 s. When run alone they
   pass. This is the timing flake noted as an E38 follow-up.

## Intended fix
1. Document the limit and change no code:
   - `docs/agents/SPEC-FORMAT.md` (the *ignored, never flagged* list) and the module docstring of
     `tools/readiness-check.py` both say that a file directly under `.harness/` (install stamps,
     per-target files) is ignored, so a typo there is not caught.
   - Add a test that pins the behaviour: `.harness/typo.py` produces no finding.
2. C8 and C8c: when the measured time exceeds the upper bound, re-run the same gate once on a fresh
   target, and fail only if the re-run also exceeds it. A regression that is slow every run is
   slow both times; an intermittent one is caught only when two runs in a row are slow. The floor checks are unchanged.
3. VERSION gets a PATCH bump, because `docs/agents` is shipped body, plus a CHANGELOG entry.

## How to verify
- `bash tests/test_readiness_check.sh`, `bash tests/test_update_check.sh` and
  `bash tests/test_docs_for_humans.sh` pass.
- `./init.sh` passes, doc-cite-check reports 0 findings, and docs-move-check exits 0.
- Mutant: the C8c retry must still fail when every run exceeds the bound. Check this by forcing the
  bound to 0 in a scratch copy.
