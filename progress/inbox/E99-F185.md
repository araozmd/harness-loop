# Fix — E39 doc follow-ups: preflight does not check the Codex App; OpenCode command files in the ownership row

## Problem / who
Operators reading the PR-loop and install docs. Found while reviewing E39-F02/F03.
1. `tools/wait-for-codex.sh preflight` checks `gh` on PATH, `gh auth`, `jq`, the repo slug, and
   that the PR is open. It cannot check whether the Codex GitHub App is installed; that only
   shows up later as watcher exit 5. Yet:
   - `docs/agents/WORKFLOW.md:858-860` lists "The Codex GitHub App … an authed gh, and jq" as
     preconditions and then says preflight "checks each one";
   - the `/sdd-pr-loop` command (`harness-install.sh:7687`, emitted to
     `.claude/commands/sdd-pr-loop.md:13` and the other front-ends) says "Step 0 verifies all
     of them".
2. The ownership row in `docs/INSTALL.md:181` says "Claude role and command files are always
   rewritten". The OpenCode command files (`.opencode/command/*.md`) are also rewritten on
   every run, and the row doesn't name them. Verify this in `harness-install.sh` before you
   change the row. If edited OpenCode command files are in fact kept, describe what really
   happens instead.

## Intended fix
- Reword both preflight sentences so they say the preflight checks `gh`, `gh auth`, `jq`, the repo
  slug and the PR, and that a missing Codex App shows up later as the watcher's exit 5 (no Codex
  activity within `HARNESS_FIRST_RESPONSE`). Edit the emitter heredoc in `harness-install.sh`,
  then run `sh harness-install.sh --self` and commit the regenerated glue.
- `docs/INSTALL.md` ownership row: name the OpenCode command files, with accurate behaviour. If
  `docs/agents/INSTALL.md` has the same claim, fix it there too.
- Update or add pins in the suites that cover these texts (`tests/test_docs_for_humans.sh`, the
  pr-loop and install suites). Add a ban on the old "checks each one" / "verifies all of them"
  wording, with a mutant.
- VERSION PATCH bump + CHANGELOG entry (📝 or 🐛).

## How to verify
- `git grep -n "verifies all of them\|checks each one"` finds nothing that claims the App is
  checked.
- The touched suites are green, `./init.sh` ok, and a second `sh harness-install.sh --self` leaves
  the tree clean. `python3 tools/doc-cite-check.py` reports 0 findings.
