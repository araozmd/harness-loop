# Fix — readiness-check: an installed-layout declaration makes its top-level directory a known root

## Problem / who
Spec authors relying on `tools/readiness-check.py` to catch path typos. Found by the E99-F184 Reviewer.
`ignored()` treats a `/` path as a reference only when its first segment is a known root: an
existing directory at the root or under `.harness/`, or the first segment of a created or deleted
path. The created/deleted comparison uses the declared path as written. A declaration in the
installed layout, such as `create .harness/newdir/x.py` with no `newdir/` on disk, therefore never
makes `newdir` a known root. As a result `newdir/x.py` and a misspelled sibling such as
`.harness/newdir/typo.py` are silently ignored instead of resolved or flagged. The source-layout
declaration (`newdir/x.py`) works. This is a missed typo, never a false rejection.

## Intended fix
- In `ignored()`, compare against each declared path with a leading `.harness/` stripped, so a
  declaration in either layout makes its first segment a known root.
- `docs/agents/SPEC-FORMAT.md` known-root clause: say "in either layout".
- Tests in `tests/test_readiness_check.sh`, written first and observed RED:
  - `create .harness/newdir/x.py` with a sibling typo `.harness/newdir/typo.py` → flagged;
  - the declared path itself → not flagged;
  - the same with a `delete` row.
