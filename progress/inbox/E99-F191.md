# Fix — drift guard falsely claims the project's planning docs; installer aborts on an unset `_cdx_cmds` after a subprocess crash

## Problem / who
Two follow-ups found while reviewing E99-F190 (#349):
1. **False drift.** `tools/harness-owned-paths.sh` `emit_body` claims everything under `.harness/`
   except eight project-owned exclusions. `/sdd-plan` writes three project-authored planning
   documents under `.harness/specs/`: `vision.md`, `architecture.md` and `adr/NNNN-*.md`. The
   Architect treats them as living documents. They are not in the install manifest's
   HARNESS-OWNED list, and upgrades never touch them. Because none of them is excluded, an
   uncommitted planning edit fails the `init.sh` drift guard, and a false positive halts the
   mandatory gate.
   Separately, the helper does not claim the root pointer block (`<!-- harness:begin -->` …
   `end`) that the installer writes into the project's own `CLAUDE.md` / `AGENTS.md`. An edit
   there is a missed drift, not a false one: the block sits inside a project-owned file, and a
   pathspec cannot claim part of a file. So this is documented, not changed. (Retired v0.78.1
   Antigravity/Gemini glue that an upgrade preserved is excluded on purpose already.)
2. **Unset variable.** `harness-install.sh` sets `_cdx_cmds` only inside
   `if skill_unit_claimed; then`. The pi block that follows (`for _c in $_cdx_cmds`) assumes
   that pi being selected implies the skill unit is claimed. Under load, one `grep` inside
   `agent_selected` crashed (`Segmentation fault: 11`). `skill_unit_claimed` then returned
   false while `agent_selected pi` later returned true, and `set -u` aborted the install:
   `_cdx_cmds: parameter not set` (seen in `test_pi_front` during a full-suite run).

## Intended fix
1. `emit_body`: exclude `specs/vision.md`, `specs/architecture.md` and `specs/adr/`, with a
   comment. State the uncovered glue (Antigravity, pointer block) in the header as a known
   limit. In `docs/agents/INSTALL.md` "Layout & ownership", add the three planning docs to the
   project-owned row.
2. Make `agent_selected` a pure shell `case` match, with no `grep` subprocess, so it cannot give
   two answers for one key in a run. Keep `_cdx_cmds` inside the block, so any future
   inconsistency still fails loudly under `set -u`. (Moving it outside, the first attempt, turned
   the abort into a silent broken pi install; the Reviewer caught it.)
3. Tests:
   - `tests/test_init_drift_guard.sh`: in the R4 fixture, uncommitted edits to all three
     planning docs do not trip the guard, and the existing positive control still does. Add
     source-level assertions that the three exclusions are emitted.
   - `tests/test_install_agent_selected.sh`: the real `agent_selected` is extracted and
     exercised for exact whole-line matching. A substring mutant and a subprocess mutant are
     both rejected.
4. VERSION PATCH bump plus a CHANGELOG entry.

## How to verify
- `bash tests/test_init_drift_guard.sh`, `bash tests/test_install.sh`, `bash tests/test_pi_front.sh`
  and `bash tests/test_docs_for_humans.sh` pass. `./init.sh` passes, `doc-cite-check` reports 0
  findings and `docs-move-check origin/main` exits 0.
